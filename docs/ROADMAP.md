# Roadmap

Term-Inator evolves through observed communication failures. The priorities below
are candidates for future work, not promised releases. A new rule should address
a reproducible problem without weakening terminology, requested formats, or the
boundary against unsolicited teaching.

## Test continuity across real conversations

Exercise actual multi-turn corrections, changing evidence, and handoffs after
compaction. Current single-prompt cases can describe earlier events, but cannot
show whether an assistant carries those events forward correctly. Success means
preserving material conditions and deferred decisions while discarding superseded
conclusions.

## Test usefulness for readers

Compare answers with and without the skill on the same tasks, including readers
with different domain knowledge. Measure comprehension errors, time to identify
the decision or next action, and self-reported mental effort. This would test
the motivation to reduce unnecessary interpretation effort; response length alone
cannot establish that benefit.

## Measure the contribution of each component

Use repeated, controlled comparisons of Term-Inator alone, a short terminology
preference, and the combined Token-Evaporator-Inator workflow. Hold the task,
model, host instructions, and companion versions fixed. Count instruction and
conversation tokens as well as output tokens, and check meaning preservation.
Publish failures and ties alongside gains so users can judge which setup helps.

## Add coverage where failures justify it

Prioritize different domains and languages, ambiguous project vocabulary, and
conflicts between concise wording and necessary context. Confirm always-on
loading separately from response quality. Keep cases portable and reproducible;
add instructions only when a smaller wording change or existing rule is insufficient.

The core remains a communication skill. A dedicated teaching workflow, if useful,
belongs in an optional companion. Requested explanations already work without one.
